CreativeOS: The Flagship Creative-Intelligence System

An orchestrated LangGraph pipeline that ingests competitor and own creative, clusters it by theme, flags fatiguing angles, generates on-brand variants, gates every output through an eval, and routes to a human for taste sign-off — instrumented with cost-per-run and a quality dashboard.

Role: AI PM — Amin

01The Thesis

The Problem

Drowning

Growth teams are drowning in creative but have no system to learn from it. Which angles are working? Which are fatiguing? What should we make next? Clustering, scoring, and generation all happen manually — or not at all — and every "AI creative tool" answer generates volume without judgment.

Strategic Pivot

A System, Not A Chatbot

Orchestration + evaluation + a data flywheel — the exact shape the MarTech market pays a premium for. CreativeOS composes two independently evaluated modules (HookLens as the labeling gate, BrandGround as on-brand grounding) into one stateful graph with branches, human pauses, and recovery.

03Architecture

The Stateful Graph

INGEST → CLUSTER/LABEL → SCORE + FATIGUE → GENERATE → EVAL GATE → HUMAN REVIEW → FEEDBACK LOOP → DASHBOARD

A LangGraph StateGraph with conditional edges: if nothing passes the gate, loop back to regenerate; if it passes, pause for the human. Any step that errors retries with backoff, then escalates instead of crashing — with iteration caps everywhere so it can never loop forever.

The Methodology

Evaluate the pipeline, not just calls: End-to-end success rate, gate pass-rate, human-approval rate, average iterations, and cost per run — because a system's failure modes live between the steps, not inside them. This is the layer ~95% of candidates skip.

Validated LLM-as-judge: Cluster coherence and variant quality are subjective, so they're scored by a judge that is itself validated against human judgments on a sample. A healthy gate pass-rate sits in the 60–80% band: 100% means the gate is asleep, 5% means generation is broken.

Regression tracking in CI: The golden set re-runs on every pull request, so a bad prompt change is caught automatically. Human approve/reject decisions feed back to update scores and grow the golden set — the data flywheel turning.

05PM Judgment

The Hard Decision

The Fatigue Proxy — Named, Not Hidden

With no live performance data (the cold start), fatigue is detected via saturation + recency proxies: an angle is fatigue-risk if enough competitors run it AND it's been circulating for weeks. The limitation is stated in the README: "This is a saturation proxy; with real ROAS data I'd replace it with measured decay." Presenting a proxy as measured truth is the failure; naming it is the signal.

The Rejected Alternative

Multi-Agent Theater

The tempting build was a multi-agent "crew" — it demos flashier. Rejected: a well-built single orchestrated graph beats a sloppy crew, and complexity has to be earned by a measured need, not fashion. Same discipline scoped the ambitious "Creative Intelligence Engine" vision down to the buildable, eval-led slice — with the honest gap documented.

The Human-In-The-Loop Boundary

Human Checkpoint 1

Final variant approval — the taste/brand sign-off a model can't own.

Human Checkpoint 2

The "spend money on this" call — never automated, ever.

Human Checkpoint 3

Tuning the fatigue threshold — a judgment about risk appetite. Everything else is automated.

The Kill / Scale Call

Cost-per-run is measured with Langfuse traces, not estimated — broken down by step on a live dashboard. The framing: "If this pipeline improves hook selection enough to lift ROAS by Y% on a $Z monthly spend, it pays back in N runs." With token prices down ~80% year-over-year, cost is rarely the blocker — quality and trust are, so the frontier model touches only where quality is visible.

07Retrospective

Gates Beat Models

Chained workflows multiply both cost and error — so validation gates and iteration caps matter more than model choice. One bad output with no gate between steps poisons the entire chain; the eval gate is the antidote to error compounding.

Spine Before Cathedral

A rough end-to-end spine shipped in week one beats an unfinished cathedral in week eight. Intelligence and evals were layered onto a running skeleton — and the next honest step is replacing the fatigue proxy with measured ROAS decay once real performance data exists.
